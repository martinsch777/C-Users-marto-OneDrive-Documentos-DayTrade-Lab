## 1. Executive Summary

The frozen `HYP-DRIVE-PB-01` discovery produced 3 confirmed events and 1,503
terminal exclusion rows across QQQ and SPY. The dominant recorded exclusion was
`EXCLUDED_DRIVE_THRESHOLD` with 1,255 rows (83.4997%). The next most frequent
was `EXCLUDED_POST_DRIVE_NEW_EXTREME` with 155 rows (10.3127%).

This explains descriptively where the frozen event definition most often
terminated. It does not identify better parameters and does not authorize a
new variant. The hypothesis remains closed as `discovery_failed`, with
`insufficient_event_frequency` as its dominant failure reason.

## 2. Scope

This review describes the exclusion ledger generated by the completed
2022-2024 discovery. It does not rerun discovery, reconstruct OHLC conditions,
evaluate counterfactual rules, or estimate event counts under alternative
parameters.

The unit of analysis is the row actually recorded in `event_exclusions.csv`.
No sequential funnel is claimed because the file records only one terminal
reason and contains no ordered filter-stage history.

## 5. Actual `event_exclusions.csv` Schema

The file has exactly three columns:

| Column | Observed meaning |
| --- | --- |
| `symbol` | QQQ or SPY |
| `session_date` | Calendar date associated with the terminal decision |
| `exclusion_reason` | Final exclusion code recorded for that symbol-session |

Each row is one terminal excluded outcome for one `symbol, session_date` pair.
The file contains 1,503 unique pairs, no duplicate pair, and a maximum of one
row per pair. It therefore demonstrates one recorded terminal exclusion per
excluded symbol-session in this run.

It does not contain an explicit stage column, timestamps of intermediate filter
evaluation, failed values, distances to thresholds, or multiple reasons. It
cannot demonstrate the order in which every filter was evaluated or whether a
later condition would also have failed.

## 10. Dominant Reasons

`EXCLUDED_DRIVE_THRESHOLD` dominates overall and within both symbols. It is
followed by `EXCLUDED_POST_DRIVE_NEW_EXTREME`. Together they account for 1,410
of 1,503 exclusion rows (93.8124%).

This concentration says that most symbol-sessions terminated at labels tied to
the frozen drive/event definition. It does not show how close observations were
to any boundary and does not establish that changing either rule would create
valid, independent, or profitable events.

## 11. Filters And Event Scarcity

The recorded labels can be separated conceptually:

| Category | Terminal reasons | What can be said |
| --- | --- | --- |
| Eligibility/data availability | `EXCLUDED_SESSION_NOT_APPROVED`, `EXCLUDED_INSUFFICIENT_ATR_HISTORY` | The session or required prior information was unavailable under the frozen contract |
| Event-selection conditions | `EXCLUDED_DRIVE_THRESHOLD`, `EXCLUDED_POST_DRIVE_NEW_EXTREME`, `EXCLUDED_MAXIMUM_PULLBACK` | The frozen event definition did not accept the symbol-session |

The CSV does not establish a full ordered funnel. A terminal selection reason
is not itself an economic cause for return behavior, and an eligibility reason
is not evidence against the economic mechanism.

The descriptive conclusion is limited: the complete frozen conjunction yielded
only three accepted events. It cannot isolate the marginal effect of each
condition because only the terminal reason is retained.

## 12. Limitations

- No intermediate filter outcomes or failed numeric values are present.
- Only one terminal reason is recorded per excluded symbol-session.
- Counterfactual eligibility under different rules cannot be calculated from
  this ledger.
- Terminal-reason frequency is not a measure of economic importance.
- The three accepted events are too few for causal or economic inference.
- This analysis does not distinguish near misses from observations far beyond
  a boundary.

## 13. Anti-Overfitting Restriction

This post-mortem must not be used to reduce the drive threshold, increase the
maximum pullback, widen windows, change confirmation, move cutoffs, remove
filters, or otherwise produce more historical events.

No what-if analysis was performed. No alternative threshold, window,
confirmation, orientation, or filter was evaluated. Any new hypothesis must be
independent, separately designed, human-approved, and frozen before historical
results are opened.

## 14. What Cannot Be Inferred

The ledger cannot show:

- that the drive threshold was too high or low;
- that a different pullback boundary would improve evidence;
- how many events another definition would produce;
- whether excluded sessions would have profitable future paths;
- which filter should be removed;
- that event scarcity caused the negative net result;
- that the broad economic idea is universally false.

## 15. Descriptive Conclusion

The frozen HYP-DRIVE-PB-01 definition produced extremely low evaluable
frequency: 3 confirmed events from 1,505 approved symbol-sessions. Most
excluded symbol-sessions ended with the terminal label
`EXCLUDED_DRIVE_THRESHOLD`, followed by
`EXCLUDED_POST_DRIVE_NEW_EXTREME`.

That is the complete permitted conclusion. The result supports closure of this
variant as `discovery_failed`; it does not support new parameter values,
retrospective relaxation, or a HYP-DRIVE-PB-02 proposal.
